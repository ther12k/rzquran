# ADR-002

**State: accepted — direct owner instruction, 2026-09-07. This amends ADR-001's repository placement only; ADR-001's technical choices remain in force.**

## Context

ADR-001 proposed adding the shared Godot project "in the existing repository" (`ther12k/rz-quran`). On 2026-09-07 that repository was inspected: branch `main` at `f1b43db`, clean and synced, with the reported SHA `669c5e3` present in history and the M0–M5 deliverables described in the bundle's project context. The baseline exists and materially matches the report.

The owner has now directed that the MVP work live in a **new dedicated repository** rather than inside `rz-quran`. This document records that decision; the documentation bundle was extracted as the new repository's initial content.

## Decision

- The new dedicated repository (this checkout) holds: this OKF documentation package, the Godot 2D client project (typed GDScript, web + Android debug exports), the accessible HTML equivalent activity, and client build/export tooling and CI.
- `rz-quran` remains the **only** backend and keeps the React parent/admin areas. Any endpoint additions or contract mappings required by [the API contract](../contracts/api.md) are implemented in `rz-quran` only. No second backend is created.
- The two repositories couple exclusively through the documented API contract, content release rules, and the existing parent summary. Client evidence records the client commit SHA and, whenever backend behavior is exercised, the backend commit SHA.
- GDM issue texts that say "the existing repository" are read with this amendment applied: client-side work belongs to the new repository; server/parent-dashboard work belongs to `rz-quran`. Issue bodies are not rewritten or renumbered, so their recorded hashes stay valid.

Unchanged from ADR-001: shared typed GDScript scenes, Compatibility renderer, single-threaded web export, narrow platform adapters, staging-only Android pairing, and the server's sole authority over authorization, answer validation, idempotency, completion, and progress.

## Consequences

- Acceptance evidence and traceability become cross-repository: milestone reports must cite both client and backend SHAs when both are exercised.
- Local development runs the `rz-quran` stack (Bun/Elysia/PostgreSQL) alongside this repository's export preview; both READMEs need a short startup-order note.
- CI stays split: client builds and artifacts in this repository; backend suites and security scans remain in `rz-quran`.
- The feature-flag rollback named in ADR-001 protects the React flows inside `rz-quran`; this repository can be discarded or rebuilt without touching parent/admin behavior.
