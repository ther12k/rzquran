## Scope

- Triage every observed finding with severity/owner and either fix or justified disposition.
- Rerun affected tests plus the critical web/Android journey on the revised candidate.

## Acceptance criteria

- [ ] Every pilot finding has a traceable disposition; no unresolved critical/high security or critical content defect remains.
- [ ] Fix evidence identifies code/build changes and affected regressions.
- [ ] If no defects were observed, actual pilot evidence supports that finding; the task is not auto-closed before the pilot.

## Verification and evidence

Execute QA-44 from the [test plan](../../qa/test-plan.md). Attach commit/build/content identifiers, actual commands and outcomes, relevant artifact paths/hashes, and explicitly unexecuted checks using the [evidence template](../../qa/evidence-template.md). For human gates and pilots, record actual external evidence; code or a template cannot supply it.

## Exclusions

No unapproved external deployment, fabricated evidence, unrelated platform rewrite, hidden scope narrowing, production native login, app-store publication, or native iOS completion claim. Passing engineering checks does not imply human approval. Follow [agent rules](../../AGENTS.md) and [scope](../../product/scope.md).
