## Acceptance criteria

- [ ] Required web and native Android journeys pass using synthetic profiles and permitted fixture/learning assets.
- [ ] Security, device, accessibility and performance checks have executed evidence or explicit failed/blocking status.
- [ ] The report states whether only fixtures were exercised; it does not declare curriculum, pilot, production, or native iOS approved.

## Verification and evidence

Execute QA-40 from the [test plan](../../qa/test-plan.md). Attach commit/build/content identifiers, actual commands and outcomes, relevant artifact paths/hashes, and explicitly unexecuted checks using the [evidence template](../../qa/evidence-template.md). For human gates and pilots, record actual external evidence; code or a template cannot supply it.

## Exclusions

No unapproved external deployment, fabricated evidence, unrelated platform rewrite, hidden scope narrowing, production native login, app-store publication, or native iOS completion claim. Passing engineering checks does not imply human approval. Follow [agent rules](../../AGENTS.md) and [scope](../../product/scope.md).
