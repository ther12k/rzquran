# ADR-001

**State: proposed; owner acceptance required.** This ADR applies only to the one MVP activity and does not approve external deployment.

## Context

The user wants mobile-browser testing now and installed mobile applications later. The existing implementation is reported to have React parent/admin interfaces and a Bun/Elysia/PostgreSQL backend. Rebuilding those provides no necessary value for this activity.

## Decision

Add one shared Godot 2D project in the existing repository. Use typed GDScript, the Compatibility renderer, and single-threaded web exports. Web export depends on WebAssembly/WebGL 2.0; current Godot 4 C# projects do not export to web.[^web] Pin the actual compatible stable editor and matching export templates in GDM-002 rather than guessing a version from earlier chat.

Keep React for account entry, parent/admin operations, runtime loading/failure UI, and an equivalent HTML activity. Godot handles child presentation and interaction. Keep current backend/data/content services authoritative. Add thin contract mappings only where needed.

Browser platform functions go through a narrow host bridge. Native uses HTTP to the same application services. `JavaScriptBridge` is web-specific; `HTTPRequest` provides HTTP client functionality.[^bridge][^http] Shared scenes must not import either platform adapter directly.

Android receives an internal staging-only grant flow for testing, not a new production authentication system. Native iOS export and store delivery are deferred; iOS export requires macOS with Xcode.[^ios]

## Alternatives rejected for this MVP

Full Godot rewrite: needless duplicate adult/admin workflows. Native WebView wrapper: would not validate the actual shared native game client. React-only new game: does not prove the desired native Godot path. Full native OAuth/refresh/keychain system now: out of scope for synthetic-profile internal testing and requires its own security review.

## Consequences

Two UI presentations share one authoritative session contract. Export/build tooling is new. Web startup payload, mobile audio, Arabic rendering, interruptions, and accessibility require fresh device evidence. Existing React measurements are not transferable.

Review this ADR if accessible equivalence, web startup targets, or native-safe adapters cannot be delivered. Retain the old child route behind the feature flag until new acceptance is complete.
